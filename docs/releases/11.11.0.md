# SirisOS 11.11.0

**Update SirisOS from SirisOS, Sections you use, and version numbers that can't clash.**

## Update now

Status has a **SirisOS** card with the running version. When main on GitHub has a newer one, it says so with that release's headline and a link to what's new.

**Update now** asks for your Terminal 2FA code, then runs `make update` on the server through the Terminal, like any terminal shortcut. The update:

- runs by itself on the server, because it restarts SirisOS halfway through;
- shows on the page, which loads the new version once it answers, after a few minutes;
- leaves its log in `data/logs/update.log`, which the card shows.

It's also a Terminal shortcut, **Update SirisOS**. The server checkout is `SIRISOS_SOURCE_DIR` (`~/Docker/SirisOS/SirisOS`). It needs the Terminal set up with 2FA; without it, `make update` on the server still works.

New: `GET /api/v1/updates` (`?fresh=1` checks GitHub now).

## Sections you use

Home has a second tab, **Sections you use**:

- each section, with how many days in the last four weeks you opened it, and its tabs;
- most used first, and "not opened" for the rest;
- when counting began (11.10.0 started it), with a note that about a month gives a fair picture;
- **Hide** takes a section out of the side menu. It's still in search, its address still works, and it shows in the menu while you're in it. Home can't be hidden.

New: `PUT /api/v1/home/usage/menu {hidden}`, and the usage includes `counting_since` and `menu_hidden`.

## Version numbers that can't clash

Two changes both shipped 11.9.0 on 26-27 November: each was numbered from the same main.

- **CI checks a pull request's version is newer than main's.** If it isn't, it fails with what to run.
- **`scripts/bump-version.sh rebase`** renumbers a branch onto the next version after main's. It keeps the size of the change (fix, feature or section) and moves the version files, the README line, the release notes (file and heading) and the roadmap line. Main's own notes and line of the same number stay as they are.
- **The release step fails loudly** when a version was already released from another change, instead of skipping it quietly.

## With SirisAI 4.30.0

- **Known fixes, applied.** SirisAI now does these by itself, within a budget, and says so:
  - restarts a stopped companion container (the Obsidian relay);
  - switches to a service's new address on this server (Hermes);
  - reloads an AI model that spilled into system RAM back onto the GPU.
- **A single wrong self-test answer** goes into Sunday's report instead of a card on Home. Three nights running, it's a card.

## Update

`make update` on the server, or **Update now** on Status from now on. Then open SirisOS once so the new version loads.
